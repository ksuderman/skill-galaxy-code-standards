# Galaxy Client Patterns

Source: `gx-review-ui-components` and `gx-vitest-review` in gx-arch-review.

## Galaxy components replace Bootstrap-Vue

### GButton (replaces BButton)

```vue
<!-- Deprecated -->
<BButton variant="primary" size="sm" :disabled="busy">Submit</BButton>

<!-- Correct -->
<GButton color="blue" size="small" :disabled="busy">Submit</GButton>
```

- `variant` becomes `color`: grey (default), blue, green, yellow, orange, red
- `size="sm"` becomes `size="small"`: small, medium, large
- Tooltips are built in through the `tooltip` prop
- Polymorphic rendering:

```vue
<GButton @click="action">Button</GButton>     <!-- renders <button> -->
<GButton href="/page">Anchor</GButton>        <!-- renders <a> -->
<GButton to="/route">Router Link</GButton>    <!-- renders <router-link> -->
```

Source: `client/src/components/BaseComponents/GButton.vue`

### GLink (replaces BLink)

```vue
<!-- Deprecated -->
<BLink href="#" @click="doSomething">Click here</BLink>

<!-- Correct -->
<GLink @click="doSomething">Click here</GLink>
```

Source: `client/src/components/BaseComponents/GLink.vue`

### GModal (replaces BModal)

```vue
<!-- Deprecated -->
<BModal v-model="showModal" title="Confirm" ok-only>Content</BModal>

<!-- Correct -->
<GModal v-model:show="showModal" title="Confirm" confirm>Content</GModal>
```

- Native `<dialog>` element
- `v-model` becomes `v-model:show`
- `ok-only` becomes `confirm`

Source: `client/src/components/BaseComponents/GModal.vue`

### GCard (replaces BCard and hand-rolled card layouts)

```vue
<!-- Deprecated custom layout -->
<div class="workflow-card">
  <div class="card-header"><h3>{{ name }}</h3></div>
  <div class="card-body">{{ description }}</div>
</div>

<!-- Correct -->
<GCard :id="id" :title="name" :description="description" />
```

Source: `client/src/components/Common/GCard.vue`

### Tooltips

```vue
<!-- Deprecated (directive) -->
<BButton v-b-tooltip.hover title="Click me">Button</BButton>

<!-- Correct (integrated prop) -->
<GButton tooltip title="Click me">Button</GButton>
```

### Standard props for new base components

```typescript
import type { ComponentColor, ComponentSize } from "./componentVariants";

interface Props {
  color?: ComponentColor;       // grey, blue, green, yellow, orange, red
  size?: ComponentSize;         // small, medium, large
  disabled?: boolean;
  title?: string;
  disabledTitle?: string;
  tooltip?: boolean;
}
```

Supporting sources:
- `client/src/components/BaseComponents/componentVariants.ts`: type definitions
- `client/src/components/BaseComponents/composables/clickableElement.ts`: element type from props
- `client/src/components/BaseComponents/composables/currentTitle.ts`: disabled title switching
- `client/src/components/BaseComponents/GTooltip.vue`: tooltip integration

Migration example PRs in galaxyproject/galaxy: #19963 (buttons), #20063 (links),
#20168 (modals), #19785 (cards).

## Vitest practices

The reviewer is a skeptic of autogenerated tests that were never red, and will tweak code
to check that each test really fails when behavior breaks. Tests get deleted when they do
not.

### Behavior, not implementation

```typescript
// Good: user-visible behavior
test('displays error message when API fails', async () => {
  vi.mocked(GalaxyApi).mockReturnValue({ error: { status: 500 } })
  const wrapper = mount(MyComponent)
  await flushPromises()
  expect(wrapper.text()).toContain('Error loading data')
})

// Bad: implementation details
test('calls fetchData method', () => {
  const fetchDataSpy = vi.spyOn(wrapper.vm, 'fetchData')
})
```

### Composition API components

```typescript
import { mount } from '@vue/test-utils'
import { describe, it, expect } from 'vitest'
import MyComponent from '@/components/MyComponent.vue'

describe('MyComponent', () => {
  it('updates count when button clicked', async () => {
    const wrapper = mount(MyComponent)
    await wrapper.find('button').trigger('click')
    expect(wrapper.text()).toContain('Count: 1')
  })
})
```

### Options API components

Test through the template, not `wrapper.vm`:

```typescript
// Good
const wrapper = mount(MyComponent, { props: { message: 'Hello' } })
expect(wrapper.text()).toContain('Hello')

// Avoid
expect(wrapper.vm.message).toBe('Hello')
```

### Pinia stores in isolation

```typescript
import { setActivePinia, createPinia } from 'pinia'
import { useAuthStore } from '@/stores/auth.store'

describe('auth store', () => {
  beforeEach(() => {
    setActivePinia(createPinia())
  })

  it('sets user on login', () => {
    const store = useAuthStore()
    store.setUser({ id: 1, username: 'test' })
    expect(store.user?.username).toBe('test')
  })
})
```

### Async, focus, names, cleanup

```typescript
const wrapper = mount(MyComponent)
await flushPromises()
expect(wrapper.text()).toContain('Loaded')
```

```typescript
// Good: one behavior
test('displays loading state', () => {
  const wrapper = mount(MyComponent, { props: { loading: true } })
  expect(wrapper.find('[role="status"]').exists()).toBe(true)
})
```

Names: `displays error banner when API returns 500`, `hides submit button when form is
invalid`. Never `works correctly` or `component test`.

```typescript
beforeEach(() => { vi.clearAllMocks() })
afterEach(() => { vi.restoreAllMocks() })
```

### Rules for generated tests

1. Do not over-test. Skip per-method and per-computed tests; cover user-facing behavior.
2. Do not test framework code. Vue and Pinia are already tested.
3. Cover edge cases: error states, empty data, boundaries.
4. Tests should break only when behavior changes, not when implementation changes.
5. Use TypeScript.
6. Mock at the right level: external services (API, router) are mocked, component logic
   runs on real data.
7. Factor repeated mount and setup code into helpers.
8. Prove each test can fail: break the behavior, watch it go red, restore. Run with
   `yarn test` from `client/`.
